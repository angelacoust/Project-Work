# Receipt-based shared expense allocation application

After shared shopping or a group activity, receipt items may need to be split among participants in different proportions. The project aims to create a mobile and web application that extracts an editable item list from receipts and calculates participant balances using verifiable rules.

## Task

Build an application for recording and settling one group's shared expenses. Users photograph a receipt, review items, specify the payer and participants, and approve the allocation. Use one currency in the MVP. Bank integration, money transfers, and tax or accounting compliance are outside scope.

## Mandatory content

Handle groups, members, receipt images, expenses, items, discounts, and allocation rules. OCR combined with an LLM or a multimodal model must suggest item names, quantities, and amounts, linked to original image regions. Uncertain and missing fields must require review.

Users must be able to choose equal, percentage-based, or fixed-amount splits. Application logic must calculate amounts, rounding, discount allocation, and balances, and flag disagreement with the receipt total. Do not update group balances before approval. Provide edit history, manually recorded settlements, and exportable summaries. Warn about potential duplicates on repeated uploads.

## Required research and design decisions

Compare basic OCR extraction with structured AI processing. On manually checked samples separated by receipt layout, measure item and amount recognition, correction effort, and entry time. Independently verify allocation, rounding remainders, and discounts on cases with known results. Define supported receipt types, refund handling, and the effect of later edits on already settled balances.

## Possible extensions

Optional extensions include multiple currencies with documented conversion rates, offline entry, and group approval.

## Technical requirements

Provide mobile camera entry and a web expense view with persistent storage. Use exact decimals or the smallest currency unit for monetary values. Test amount conservation, concurrent edits, and repeated approval.

Keep the source code in a Git repository with setup instructions, sample data, and a reproducible evaluation procedure. Separate application, persistence, and AI integration logic. AI failures or unavailability must not cause data loss; users must be able to correct suggestions. Keep service credentials server-side and exclude secrets and personal or production data from the repository.
